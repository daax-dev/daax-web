## Implementation findings

- `BreakIn.tsx` and `breakin.ts` are both required ownership-list names. On this
  case-insensitive filesystem Vite resolves both `./BreakIn` and `./BreakIn.jsx`
  to `BreakIn.ts` (the pure helper), verified with its resolver. Explicit
  `./BreakIn.tsx` resolves correctly. The two component imports use explicit
  `.tsx` plus a targeted TS5097 directive because the repository disables TS
  extension imports. Vite component tests and the actual Next production build
  both passed with that spelling; no unowned config or filename was changed.
- Correction to initial commentary: the recorded fixture does contain one ACTIVE
  transcript row, but no `process_alive`/`agent_pid`, and its control is UNAVAILABLE.
  Explicit fixture `--control` mode supplies a synthetic live process/control
  capability for that row; default replay remains byte-equivalent to the recordings.
  A signal acknowledgment never changes its events or observed state.
- The new browser spec owns a separate production Next process on 4218 with a
  temporary 0600 proof file and test-only forward-auth credentials. It exercises
  requireAuth and deriveAuthContext rather than stubbing either. The fixture
  validates the proof, subject and forwarding tripwire. It shares 7793 with the
  original spec; combined runs use one worker, as CI already does.
- `b3cb11f`: initial implementation commit. No push or PR.
- Initial targeted run: 100 passed, eight component tests failed on the filename
  resolution above. After explicit `.tsx` imports: all eight component tests pass.
- `bun run typecheck` passed after removing unsupported testing-library `exact`
